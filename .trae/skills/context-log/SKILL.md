# Context Log Skill

把可以存档的内容**整理上下文存档**，作为后续行动参考，防丢失。**写进文件的才算归档**，对话记录不算。一个问题/记录，一个文件，不同存档之间不能混淆。

## 存档位置

`context-log/` 目录，文件名格式：`<YYYY-MM-DD>_<主题关键词>.md`

## 归档类型

### 排查 bug

- 现象
- 根本原因
- 测试方式：测试脚本，测试条件和环境，如何运行测试
- 测试结果
- 修复方式：用了什么方案，相应代码

涉及多个修复方案选择一个的，参考“决策记录”部分。

### 决策记录

- 面对的问题和需求
- 预期结果
- 根本原因
- 提出的各方案：是什么，优势，不足，限制条件（若有）
- 测试：过程和结果
- 最后敲定的方案
- 决策依据

### 总结经验

从**实战经验**（而不是其他skill）出发:

- 实际做了什么
- 对应结果
- 什么操作有效
- 踩的坑
- 适用场景/必备条件/局限

实战经验，可多次使用，或者已经多次使用的，整理成项目内部 skill 备用。

## 使用方法

1. 读取或创建 `context-log/<YYYY-MM-DD>_<主题>.md`
2. 从实际结果出发，参考要点，补充内容

## 注意事项

- 整理格式不唯一，按照实际情况即可。
- 临时编号（例如A，B）不进文件，直接写采用的方案。
- 只在必要时更新存档。举例：反复测试、修改才能彻底修复的bug。注明更新日期。
- 复杂问题，涉及多个存档文件的，分别更新。
