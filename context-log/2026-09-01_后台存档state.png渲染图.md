# 后台存档 state.png 渲染图（2026-09-01）

> 决策类型：存档功能新增。关联：context-log/2026-08-27_移除stepPNG前端canvas渲染.md（同天前身：PNG 曾因前端改 canvas 渲染而被移除）。

## 面对的问题

`output/<运行ID>/` 里只有 state.json（数据），运行结束后无法快速"看图"——想离线查看每次运行的画布作品，得重开网页。需求：像 state.json 一样后台保存一张图片，每运行一个文件夹一张。

## 事实核查（改动前）

- **2026-08-27 曾移除 PNG**：当时的 `step_NNN.png` 是每步一张、URL 写进 `state["image"]`、唯一消费方是前端 `<img>`；前端改 canvas 按 grid 复刻 `(dx^dy)&a` 渲染后整条链删除，PIL 依赖也删了（requirements.txt / DEPENDENCIES.md 同步移除）。
- 本次用途不同：**纯后台存档**（web 不消费），一张/次运行，随快照覆盖写、运行结束即最终画布。不复活 `step_NNN.png` 多张方案。
- 渲染逻辑已有：`xor_world.render()` 返回 512×512 uint8 灰度 numpy 数组（0=黑/255=白），selftest 已用黑占比验证正确性。
- 环境已装 pillow 10.4.0（HPND 宽松许可证，与项目依赖约束一致；设计决策时即已列入许可审查名单）。

## 命名决策（AskUserQuestion 确认）

选定 **`state.png`**：与 state.json 平行对应——同一画布状态的两种表示（数据 + 图），同文件夹一眼对应。
- 备选 `canvas.png`（按内容命名，与 state.json 对应关系弱）、`output.png`（用户原提；缺点：文件夹已叫 output/<时间戳>/，里面再叫 output.png 语义重复，且"output"不指代内容）。

## 方案

`xor_world.snapshot(out_dir)` 在写 state.json 后追加写 `state.png`（`Image.fromarray(render()).save(...)`），随快照覆盖写。调用方零改动：agent.snap() / sim_agent / selftest 都走 snapshot。前端不读此图（不新增 HTTP 映射、不改 index.html）。

## 实施内容

| 文件 | 改动 |
|---|---|
| xor_world.py | 加 `from PIL import Image`；snapshot() 写 state.json 后追加 `Image.fromarray(render()).save(os.path.join(out_dir, "state.png"))`；docstring 更新 |
| requirements.txt | 加 `pillow>=10.0`（HPND） |
| DEPENDENCIES.md | 直接依赖表加 pillow 行；"免 PNG"结论改"后端另存 state.png 仅存档，web 不消费" |
| tests/selftest.py | 快照断言加 `assert os.path.exists(state.png)`；打印改为 `state.json + state.png` |
| README.md | 结构树 output/ 行加 `+ state.png` |
| TECH_DESIGN.md | L109 运行产物 bullet 加渲染图 state.png；L112 snapshot bullet 改写（state.json + state.png，前端不读图） |

## 测试方式与结果

1. `python tests/selftest.py`：全过。`快照 OK: output/20260901_080534/state.json + state.png`；测试运行文件夹自动清理；HTTP /output/state.json 200、白名单外 404 回归不受影响。
2. 临时探针（tempfile 目录，用完即删）：全 a=3 → `mode=L size=(512,512)`，颜色分布 65536 黑 + 196608 白 = 黑占比 0.25，与 numpy 渲染一致（a=3 为 1×1∪2×2 棋盘格）。

## 影响面

- 前端 / HTTP 层：零改动（图只存档，无映射需求；`output/<运行ID>/state.png` 走白名单本就可达，非敏感）。
- 每次快照多一次 512×512 PNG 编码（PIL，毫秒级），对 ~96 次工具调用上限无感。
- 历史遗留：output/ 顶层测试残留文件夹（output_1~6、output8、test）未动，留给用户自行清理。

## 经验

- 需求里"与 state.json 类似"要回到**上一条改动**看历史：本项目 PNG 不是"新增概念"，是 2026-08-27 移除功能的**存档用途复活**——先读旧 context-log 再动手，避免把已删除的老方案（step_NNN.png 多张）搬回来。
- 文档一致性：requirements.txt / DEPENDENCIES.md 两处必须同步（上次移除时两边一起删的，本次一起加回）。
