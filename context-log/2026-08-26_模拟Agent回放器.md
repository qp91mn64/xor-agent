# 模拟 Agent 回放器（2026-08-26）

## 背景

问题清单第 6 条：用原始真实日志数据（`xor_agent_20260826_003643.log` → `tests/example_data.txt`）模拟真实 Agent 完整决策过程，浏览器实测 UI（思考流式 / 点击轨迹 / 结束状态），不消耗 API token。

与一次性探针（`probe_*.py`，用完即删）的本质区别：探针用编造数据驱动一次测试；回放器是**可复用测试工具**（与 selftest.py 同类），常驻 `tests/` 版本控制，数据全部来自真实日志。

## 实现（tests/sim_agent.py）

### 日志解析 → 事件序列

- 时间戳行（`[YYYY-MM-DD HH:MM:SS]`）携带事件；**多行块**（思考/输出）首行带 `模型思考:`/`模型输出:` 前缀，后续不带时间戳的行累积为续行，直到下一时间戳行。
- 事件：`round`（`--- 第 N 次循环 ---`）/ `think` / `tool`（`模型调用工具: name args=json`）/ `output` / `finish` / `stats`，均带真实 ts（epoch 秒）。
- think 事件额外带 `duration` = 该轮「本轮请求耗时 Ns」（思考发生在 API 请求期间）。
- 工具结果回执行（`name id=... -> ...`）、启动诊断行与回放无关，忽略。

### 回放 = 日志时间戳倒推的真实速度（speed=1）

- **事件间隔按 ts 差推进**：`sleep((ev.ts - prev_ts) / speed)`。
- **思考流式按「本轮请求耗时」铺满**：字符块自适应分批，`BATCH_SLEEP=0.05s`（20 帧/s），文本流完后剩余时间继续 sleep（模型沉默思考阶段，不推事件），总流式时长 = duration/speed。
- **同秒事件最小间隔**：日志秒级精度丢失轮内亚秒时序，`min_gap=0.2s` 保留点击轨迹逐点可见。
- 驱动：`write_reasoning_live`（思考）+ `tools.execute_tool`（带 reasoning/round_id）+ `agent.snap`（快照），与真实 Agent 同链路；结束设置 status/final_reason + 数据完整性校验（coverage==63）。

### 推送走真实 SSE 链路

`write_reasoning_live` / `snap` 内部就是 `_sse_broadcast`（agent.py），浏览器 EventSource 连 `/events` 实时收 `reasoning`/`state` 事件；web 的 3s 轮询只是断线兜底。实测探针连接 `/events` 6 秒收到 306 帧 reasoning 事件。

## 验证

- 逻辑级（不启动服务器、sleep 压零）：事件顺序正确，72 工具 / 63 点击 / 覆盖 63/63 无未设定。
- 时长校验：思考流式总时长 197.4s ≈ 日志真实跨度 201s（差值 = 启动/轮间工具执行时间）。
- 流式批数算术验证：每轮流式总时长 = 请求耗时（stream + remain 补足）。
- 完整回放（speed=100）：8 轮 / 72 工具 / 63 点击，`统计(日志) 8/72/63` 与 `统计(实际) 72/63/63` 一致，`数据回放完整`。

## 踩坑

1. **U+2212（− 数学负号）在 GBK 控制台 print 崩溃**：第 8 轮最终总结含 `−`，`print` 抛 `UnicodeEncodeError` 中断回放，且无 traceback 可见（stderr 被吞，exit 0 假象）。修复：脚本内 `sys.stdout.reconfigure(encoding="utf-8")`（与项目 `PYTHONIOENCODING=utf-8` 约定一致，脚本自包含）。
2. **流式批次 0.3s/批 → 浏览器「一卡一卡」**（观感与轮询卡顿相似，用户据此误判「没用 SSE」）。根因是帧率仅 ~3 帧/s，不是 SSE 缺失（实测 /events 有 306 帧）。修复：批间隔 0.05s（20 帧/s），并补足剩余时长。
3. **trae-sandbox 环境进程管理坑**（IDE 终端跑命令时）：
   - blocking 命令约 2s 超时杀进程 → 长时回放「莫名只输出几行」；
   - 被杀/后台进程**残留**占端口（8765）与文件锁 → 下次运行 fallback 随机端口、输出文件写入失败；
   - 验证策略：dry-run/逻辑级验证（不起服务器、sleep 压零）、重定向文件 + Read 读（PowerShell `Get-Content` 对 UTF-8 会乱码，Read 工具按 UTF-8 正常）、`Get-CimInstance Win32_Process` 按命令行杀残留（`Stop-Process`）、`Get-NetTCPConnection` 查端口占用。
4. **验证脚本勿全量跑真实流式**：`stream_reasoning` 每次 `write_reasoning_live` 全量序列化累积文本，第 1 轮 3000+ 批会写 ~100MB，验证用**纯算术**（批数/时长公式）或 patch `time.sleep` 为累加器。
