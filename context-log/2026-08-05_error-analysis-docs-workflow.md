# Context Log - 差错分析：文档流程（命名/结构/审查门）

创建时间: 2026-08-05
分类框架：诺曼《设计心理学1：日常的设计》（增订版中译本）。差错=失误+错误；失误=行动失误+记忆失效；错误=违反规则+缺乏知识+记忆失效。

## 差错清单（现象）

1. **流程**：设计讨论收敛后，没有先对文档做整体审查，也没用 Trae 的 /plan、/spec 工作流；代码写完后才发现文档不合理（好在本地开发阶段就发现，但存在潜在返工）。
2. **命名**：设计文档用了 DESIGN.md——不符合 2026 年 AI 生态惯例（已被 Google Labs 的 DESIGN.md 视觉设计系统规范占用），最初无人发现。
3. **结构**：文档没有先写整体架构再写细节（先写了工具协议）；实现约束有歧义（地址/端口形式未唯一化）。

**发现机制**：看代码看到 `127.0.0.1`，与之前项目用过的 `http://localhost:8080` 形式不同，才触发拷问。

## 差错分类（逐条映射）

| 差错 | 类型 | 具体机制 |
|---|---|---|
| 1a 没先审查文档 | 表面：失误（记忆失效/行动遗漏）；深层：计划层面就没有审查门 | 意图存在（要清晰文档），但"审查"这一步没进入计划/执行。深层看不是个人失误，是流程设计缺门 |
| 1b 没用 /plan /spec | **可能是合理选择，不是差错**（见根因 R5） | /plan /spec 是执行导向工作流；本次是探索型任务 |
| 2 DESIGN.md 命名 | 错误——缺乏知识 | 不知道/没想起 DESIGN.md 在 2026-03 起已被 Google Labs 规范定义为"视觉设计系统文件"；惯例变更而知识未更新 |
| 3a 结构顺序（先细节后整体） | 错误——违反规则 | "先整体后细节"的写作原则未被执行（且当时 AGENTS.md 无此规则，属规则缺位） |
| 3b 实现约束歧义 | 错误——违反规则/知识型 | 约束未写成"唯一实现"；AGENTS.md 的"唯一实现"规则是事后才补 |

**出处（已核实 2026-08-05）**：DESIGN.md 视觉设计系统规范原始链接 = [github.com/google-labs-code/design.md](https://github.com/google-labs-code/design.md)（Apache-2.0，"A format specification for describing a visual identity to coding agents"，2026-04 起活跃，现 v0.4.0）；介绍页 [designmd.app/what-is-design-md](https://designmd.app/what-is-design-md)。

## 根因分析（多因、系统性，不怪人）

**R1（主因）流程缺"强制功能"（forcing function）**：讨论→文档→代码的链路里没有审查门。AGENTS.md 只有"修改后检查一致性"（反应式），没有"产出前审查"（预防式）。诺曼的原则：差错若反复出现，先怀疑系统设计，而非个人失误。这次三个差错都指向同一个流程缺口。

**R2 知识缺口**：DESIGN.md 的语义变化（2026 年起）双方都不知道；"查行业惯例"不是流程步骤。

**R3 经验未显式化（记忆失效）**：localhost:8080 的既有经验只存在记忆里，没在开始时成为设计约束 → 事后对照才触发发现。

**R4 规则缺位**："先整体后细节""唯一实现"当时都不在 AGENTS.md。

**R5 对"没用 /plan /spec"的复核**：/plan /spec 是执行导向（有内置"暂停确认"= 强制功能，适合从零搭建/重构）。本次是"先发散后收敛"的探索型讨论，直接套用未必合适。真正的缺口不是"没选某个工作流"，而是"收敛后没有固化+审查"。故 1b 标记为**可能是合理选择**，是否成立待你确认（你认可此推断有道理但个人经验有限，标记为**待验证**）。

## 设计问题 / 时间压力 / 社会压力

- **设计问题**：有，且是主因（R1 流程缺强制功能、R4 规则缺位）。文档作为"产物"有缺陷，根源在"产出文档的流程"没有内置审查。
- **时间压力**：本次会话无硬性时间压力证据。不硬套。
- **社会压力**：无证据。
- 需标注（未证实）：用户有熬夜/赶工的行为模式记录；若有赶工心态会加重"跳过审查"类失误。此为推断，本次会话无直接证据。

## 责任边界（不怪人，也不豁免工具）

- 命名与结构均出自 AI 产出。归因原则：
  - **不怪 AI**：工具无意图、无道德责任；且本次属真实知识缺口（DESIGN.md 规范 2026-03 才发布，不在我的知识里），**不属于"明知而不为"的例外**。
  - **不豁免工具**：AI 的两个系统性弱点暴露：(a) 知识有时效，默认不查行业惯例；(b) 文档生成没有内置"先整体后细节、约束唯一、查惯例"的强制规范。
  - **人的角色**：用户有最终确认权，但知识缺口面前人无法拦截自己不知道的东西 → 不能靠"人把关"，要靠**流程强制功能**。

## 对用户判断的复核（用户问"我现在的判断里有没有差错"）

1. "没用 /plan /spec 是流程问题"——**部分成立，但有误判风险**：探索型任务直接套执行导向工作流未必对；缺口在"固化+审查"，不在工作流选择（R5）。
2. "DESIGN.md 名字不合常理"——**成立**，且要补一句：2026-03 之前 DESIGN.md 作设计文档名是常见惯例，问题本质是"惯例变了、知识没更新"，支持知识型错误归因。
3. "差错往往不是单一原因"——你已自己指出，与诺曼一致。但"根本原因"≠"单一原因"：根因分析是识别**系统性因素组合**（R1-R4），不是找唯一元凶。
4. 潜在心智模型："AI 会不会跑偏"——真实风险存在（本次文档层确实跑偏），但兜底机制有效：**代码层零差错**（离线自测全过，渲染/指标/工具/HTTP 均正确）。应对应是"流程兜底"，而非"怀疑一切产出"。
5. **自测的边界（用户提出，正确）**：离线自测验证的是"代码实现了文档"，**不验证"文档设计本身是否合理"**（命名、结构、技术栈、架构）。"代码层零差错"与"设计可能有误"是两件独立的事——之前用"代码层零差错"来宽慰，表述范围超出证据，属分析中的失误。

## 防再犯建议（强制功能清单）

1. **文档产出前自检**（已写入 AGENTS.md 文档原则，2026-08-05）：
   - 命名：查惯例（AI 生态文件命名变化快，如 DESIGN.md 语义 2026 年已变）
   - 结构：先整体后细节
   - 约束：唯一实现、不并列替代方案
   - 与代码对照
2. **关键决策在讨论时就写进文档**（写进文件的才算归档）——避免决策只存在于对话里。
3. **/plan /spec 的场景判断**：执行导向任务可用（其内置确认暂停就是强制功能）；探索型任务用"双钻→固化→审查"。
