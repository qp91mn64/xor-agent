## 现象

- 日志完整记录了最后一轮 `模型输出: 全部 64 个区域已设定完成……`（一大段 Markdown 最终总结，见日志第 1434–1465 行），随后 `成功：模型直接输出文字…… 已点击 63/63`。
- 网页「AI 决策过程：思考 + 点击」卡里能实时看到思考与点击轨迹，但**看不到这段最终总结正文**；状态行只有机器生成的结束原因文案（如「成功：模型直接输出文字，未再调用工具。已点击 63/63」，来自 `state.final_reason`），不含总结正文。

## 根因初判（代码级证据，未跑浏览器实测）

- web/index.html 只消费两类事件：SSE `reasoning`（思考，见 `reasoning` 监听）与 `state`（点击/画布）。**没有 content（模型正文输出）的展示区/数据通道**。时间线分组只渲染 `round` 组 + 思考 + `cells`（点击），`final_reason` 只显示在状态栏。
- agent.py：`chat_stream` 只把 `reasoning_content` 经 `write_reasoning_live` 推给 web；`msg.content` 只经 `logger.log_model_response`（agent.py 第 465 行）写入日志文件与打印控制台，**从不推送 web**。
- sim_agent.py：`parse_log` 正确解析出 `output` 事件（含最终总结），但 `replay()` 对 `output` 事件**只 print 到控制台**（第 231–232 行），未推送到 web 任意通道 → 模拟回放同样看不到。
- 结论方向：最终总结缺一条“模型正文 → web 展示”的通路；真实运行与模拟回放同样缺失（旧样例 example_data.txt 第 8 轮也有总结，应同样未显示，此前未专门注意）。
