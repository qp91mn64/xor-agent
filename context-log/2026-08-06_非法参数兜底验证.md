# 探针验证：模型非法参数兜底（tools.py _require_int）

日期：2026-08-06

## 背景

- 静态审查发现崩溃隐患：模型发出非法 tool_call 参数时，修复前 tools.py `arguments["index"]` 直接索引会抛 KeyError / TypeError，且该调用在 agent.py 的 try 之外，主循环直接崩。
- 修复：tools.py 增加 `_require_int`，在工具边界校验存在性 + 类型（整数、非 bool），非法一律返回 `Invalid: ...` 文本，喂给 agent.py 已有的连续无效点击计数。
- 实证：全部历史运行日志中模型从未发过非法参数（17+ 个日志，0 次字符串/缺键/非对象，0 次 Invalid），本次为纯兜底验证，非事故复盘。

## 探针脚本（probe_bad_args.py，已删除，代码存档于此）

```python
"""探针：模拟模型发出非法参数的 tool_call，验证 tools.py 的兜底（Invalid 而非崩溃）。

对应 agent.py 中 `json.loads → execute_tool` 的崩溃点（tools.py 修复前）：
1. value 传字符串 "5"        -> 修复前 xor_world 里 DATA_MIN <= "5" 抛 TypeError
2. index 传字符串 "5"        -> 同上
3. 缺 value 键               -> 修复前 arguments["value"] 抛 KeyError
4. arguments 非法 JSON       -> json.loads 兜底 {}，修复前 arguments["index"] 抛 KeyError
5. arguments 合法但非对象     -> 修复前对 list 索引抛 TypeError

全部离线，不依赖 API。
"""

import json

import tools
import xor_world

xor_world.init(seed_value=0, seed_index=0)  # 与 agent.py main() 一致，先初始化画布


def simulate(raw_args):
    """复刻 agent.py L339-343 的工具调用段"""
    try:
        arguments = json.loads(raw_args)
    except json.JSONDecodeError:
        arguments = {}
    return tools.execute_tool("set_region", arguments)


BAD_RAW_ARGS = [
    '{"index": 1, "value": "5"}',  # 模型把 value 传成字符串
    '{"index": "5", "value": 1}',  # 模型把 index 传成字符串
    '{"index": 1}',                # 缺 value 键
    "not-json-at-all",             # json.loads 失败（agent.py 兜底为 {}）
    "[1, 2]",                      # 合法 JSON 但不是对象
]

print("=== 非法参数 → 期望全部返回 Invalid，不抛异常 ===")
all_invalid = True
for i, raw in enumerate(BAD_RAW_ARGS, 1):
    result = simulate(raw)
    ok = result.startswith("Invalid")
    all_invalid &= ok
    print(f"[{i}] raw={raw!r}\n    -> {result}\n")

print("=== 对照：修复前（直接索引）同输入会怎么崩 ===")
try:
    arguments = {}  # 场景 4 的兜底结果
    arguments["index"]  # 修复前 tools.py 的写法
    print("    意外：没崩")
except KeyError as e:
    print(f"    KeyError: {e} —— 修复前主循环在这里直接崩掉")
try:
    arguments = {"index": 1, "value": "5"}
    assert -64 <= arguments["value"] <= 63  # 修复前 xor_world 的范围检查
except TypeError as e:
    print(f"    TypeError: {e} —— 修复前字符串 value 在这里崩掉")

print("=== 正常输入不受影响 ===")
print(tools.execute_tool("set_region", {"index": 1, "value": 2}))
print()

assert all_invalid, "存在未按预期返回 Invalid 的非法输入"
print("兜底验证通过：5 类非法参数全部返回 Invalid，主循环不会崩。")
```

注：上面探针里的「对照：修复前」是**复刻**（用相同表达式现场演示），不是跑修复前原版代码。
修复前原版的真实崩溃行为见下文「修复前原版实测」一节（git HEAD:tools.py 直接运行）。

## 修复前原版实测（git HEAD:tools.py 真原版，未动工作区代码）

方法：`git show HEAD:tools.py`（修复前原版，本会话改动未提交）字节原样导出到临时文件，
importlib 加载后对同样 5 类坏参数调用原版 `execute_tool`，捕获真实异常。不修改工作区，无需"改回去再改回来"。

```python
"""探针：用 git 里 HEAD:tools.py 的【修复前原版】execute_tool 重跑 5 类坏参数，抓真实崩溃。

不修改工作区代码（不动当前 tools.py），直接从 git 历史取原版：
1. git show HEAD:tools.py -> 临时文件（字节原样落盘，避免 PowerShell 重编码）
2. importlib 以模块加载原版
3. 对 5 类坏参数调 old.execute_tool，捕获并打印真实异常类型
"""

import importlib.util
import json
import subprocess
import sys
import tempfile
import os

import xor_world

xor_world.init(seed_value=0, seed_index=0)

out = subprocess.run(["git", "show", "HEAD:tools.py"], capture_output=True, check=True).stdout
tmp = os.path.join(tempfile.gettempdir(), "old_tools_probe.py")
with open(tmp, "wb") as f:
    f.write(out)
spec = importlib.util.spec_from_file_location("old_tools", tmp)
old = importlib.util.module_from_spec(spec)
sys.modules["old_tools"] = old
spec.loader.exec_module(old)

print("=== 修复前原版 execute_tool（git HEAD:tools.py）真实行为 ===")
BAD = [
    '{"index": 1, "value": "5"}',  # value 字符串
    '{"index": "5", "value": 1}',  # index 字符串
    '{"index": 1}',                # 缺 value 键
    "not-json-at-all",             # json.loads 失败（兜底 {}）
    "[1, 2]",                      # 非对象
]
for i, raw in enumerate(BAD, 1):
    try:
        arguments = json.loads(raw)
    except json.JSONDecodeError:
        arguments = {}
    try:
        result = old.execute_tool("set_region", arguments)
        print(f"[{i}] raw={raw!r}\n    -> 未崩: {result}")
    except Exception as e:
        print(f"[{i}] raw={raw!r}\n    -> {type(e).__name__}: {e}")
```

    -> TypeError: '<=' not supported between instances of 'int' and 'str'
[2] raw='{"index": "5", "value": 1}'

[3] raw='{"index": 1}'
    -> KeyError: 'value'

    -> KeyError: 'index'

原版 5 类坏参数全部真实崩溃（3 个 TypeError + 2 个 KeyError），且崩溃点在 agent.py 的工具调用段之外
（[agent.py L343](agent.py 内 execute_tool 调用处) 无 try 包裹），主循环必崩。与修复前静态推断完全一致。

## 结论

- 5 类非法输入（value/index 为字符串、缺键、JSON 解析失败、非对象）全部返回 `Invalid: ...`，主循环不崩，且结果会走 agent.py 已有的连续无效点击计数与 MAX_INVALID 中止。
- 合法输入行为与修复前完全一致（区域正常设置），无回归。
- 修复前同输入的崩溃形态已用 git HEAD:tools.py 原版实测确认（3×TypeError + 2×KeyError，见上节），与静态推断一致。
- 实测中模型从未发过非法参数（历史日志 0 命中），本探针为保险验证。
