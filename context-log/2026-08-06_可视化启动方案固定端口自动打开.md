## 背景

agent 启动后流式思考立即刷屏，把打印的可视化网址刷出视野，用户找不到网址。探针对比四个方案：A 固定端口、B 自动打开、C 组合、D 网页 UI 启动。

## 决策：选 C（固定端口 + 自动打开）

- 交互权衡（用户看重使用体验）：C 是"命令行为中心"，网页是观察窗；D 是"网页为中心"，控制+观察都在网页。D 的"重新启动/翻日志"价值取决于是否补参数表单与多轮历史，否则只是 C 换皮；而 PNG 文件始终保存在磁盘 output/（与网页是否存活无关），C 足以覆盖用户"跑→看图→改→再跑"的习惯。
- 技术实现：C 改动集中在 agent.py；D 需新增常驻宿主 + 子进程 + 页面表单，显著复杂。
- 后续：若实际使用中"运行完想在页面再看/重跑"成为痛点，可升级 D——D 可建立在 C 的核心逻辑之上。

## 实现要点（agent.py）

1. 默认端口固定 **8765**（避开 8123=Home Assistant 默认端口）；被占时自动 fallback 随机并打印实际端口；`--port` 可覆盖（0=随机）。fallback 传 `port=0` 是交给 OS 分配空闲临时端口（ephemeral port），Windows 默认范围 **49152–65535**（实测 `netsh int ipv4 show dynamicport tcp`：启动端口 49152、端口数 16384）；OS 只分配空闲端口，fallback 后不会再撞已占用端口。
2. **allow_reuse_address=False**（socketserver.ThreadingTCPServer 子类）：Windows 端口复用坑，固定端口 fallback 必须，否则与占用者共存、fallback 永不触发（详见同目录 allow-reuse-address 记录）。
3. 启动后 `webbrowser.open(url)` 自动打开；`--no-open` 关闭。
4. **敏感文件拒绝**：`.env` 等点文件、`*.log`、`probe_*`/`_` 前缀一律 404——实测 SimpleHTTPRequestHandler 不隐藏点文件（/.gitignore 可下载），服务根目录=项目根时 .env 可被本机下载。
5. 服务根目录 `directory=BASE`（脚本所在目录），不依赖 cwd，防止从系统盘启动暴露目录。
