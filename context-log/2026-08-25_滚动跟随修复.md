# 滚动跟随修复：方向感知 + 回到底部按钮（2026-08-25）

> 对应 context-log/2026-08-25_待修问题清单.md 第 3 条。用户选定交互方案后实施，浏览器实测通过。

## 根因

- 旧逻辑（2026-08-25_SSE实时推送.md 定稿）：`autoFollow = (scrollHeight - scrollTop - clientHeight < 40)`，恢复完全依赖"用户手势最后一次 scroll 事件落在距底 < 40px 内"。
- 失败机制：内容持续追加（SSE 思考 delta）使 scrollHeight 增长 → "底部"是移动靶；用户向下滑看到新内容就停手，停手点距底常 > 40px → 不恢复；一旦没恢复，内容继续涨，再滑可能再差一点 → 负反馈，"很难成功"。
- 附注：`40` 阈值同时管"暂停"和"恢复"。单独放大恢复阈值会让翻历史时（距底仍在放大后的阈值内）被下一次追加拉回底部，打断阅读 → 必须暂停/恢复分离 + 方向感知。

## 交互决策（用户选定）

「按钮兜底 + 方向感知自动恢复」：
1. 向上滚动且距底 ≥ 40px（PAUSE_DIST）→ 暂停跟随，内容照常追加不打扰；
2. 向下滚动且距底 < 150px（RESUME_DIST）→ 自动恢复跟随；
3. 暂停时时间线右下角浮现「↓ 回到底部」按钮，点击必回底并恢复。

## 代码改动（web/index.html）

- HTML：`#timeline` 外包 `#timeline-box`（position:relative），内加 `<button id="follow-btn" hidden>↓ 回到底部</button>`。
- CSS：`#follow-btn` 绝对定位（right:8px bottom:8px）、绿底 #2a7、圆角 4px、阴影、z-index 2；hover #3c9。
- JS（替换原滚动块）：
  - `const PAUSE_DIST = 40; const RESUME_DIST = 150;`
  - scroll 监听：`dist = scrollHeight - scrollTop - clientHeight`；`dirDown = scrollTop > lastScrollTop`（用 `lastScrollTop` 记录最近一次滚动位置，程序化滚动时在 `scrollToBottomIfFollow` 里同步更新，防方向误判）；`dirDown 且 dist<150 → autoFollow=true`；`!dirDown 且 dist>=40 → autoFollow=false`。
  - `scrollToBottomIfFollow()`：autoFollow 时 `scrollTop = scrollHeight` 并同步 `lastScrollTop`；随后 `$('follow-btn').hidden = autoFollow`（按钮显示 = 暂停态）。
  - 按钮 click：`autoFollow=true; scrollTop=scrollHeight; lastScrollTop 同步; hidden=true`。

## 探针代码（probe_follow.py，已删，运行方式同 probe_sse.py：不需 API key）

```python
"""验证智能跟随滚动（探针，不需要 API key）：
服务端模拟 SSE 流：多轮历史（思考+点击）撑高时间线 → 持续追加实时思考（模拟移动靶底部）。
浏览器端人工验证交互：初始跟随 / 向上翻暂停+按钮浮现 / 向下滚恢复 / 点击「回到底部」按钮。
"""
import threading
import time

import agent
import xor_world

httpd, port = agent.start_server(agent.BASE, 8899)
print(f"[0] server port={port}", flush=True)


def pump():
    xor_world.init(seed_value=5, seed_index=0)
    line = ("第{}段思考。模拟流式 delta 文本，用于撑高时间线使其超过 max-height 460px 出现滚动条。"
            "这段文字写得比较长，让每条历史轮思考占多行。")
    for r in range(1, 16):
        agent.write_reasoning_live(r, "\n".join(line.format(r) for _ in range(6)))
        for i in range(4):
            idx = r * 4 + i
            if idx >= 63:
                break
            reason = f"第{r}轮思考：\n" + "\n".join(line.format(r) for _ in range(5))
            xor_world.set_region(idx, idx - 32, reasoning=reason, round_id=r)
            agent.snap(idx)
        time.sleep(0.15)
    # 持续追加实时思考：文本逐次增长，让 scrollHeight 持续变大（模拟"底部移动靶"）
    k = 0
    while True:
        k += 1
        agent.write_reasoning_live(16, "第16轮实时思考…" + "追加文本" * (5 + k))
        time.sleep(0.1)


threading.Thread(target=pump, daemon=True).start()
try:
    while True:
        time.sleep(1)
except KeyboardInterrupt:
    pass
httpd.shutdown()
```

踩坑（Windows 终端）：探针主循环不能写 `input()` 等 stdin——非交互终端立即 EOF → httpd.shutdown() 退出。用 `while True: sleep(1)`。进程退出后 SSE/HTTP 服务仍在（trae-sandbox 包装退出但 python 存活），需 `netstat -ano | Select-String ":8899"` 找 PID 再 `taskkill /PID n /F` 清理。

## 实测结果（browser_use，模拟 SSE 流）

### 第一轮（静态内容，逻辑分支全量）

`#timeline` 16 组内容（scrollHeight 3420、clientHeight 460），逐条合成 scroll 事件序列：

```json
1-init            {"autoFollow":true,  "btnHidden":true,  "dist":0}
2-up-far          {"autoFollow":false, "btnHidden":false, "dist":2760}  // 向上滚且距底≥40 → 暂停+按钮
3-up-near-bottom  {"autoFollow":true,  "btnHidden":true,  "dist":100}   // 向下滚且距底<150 → 恢复
4-down-to-bottom  {"autoFollow":true,  "btnHidden":true,  "dist":0}     // 贴底保持跟随
5-up-again        {"autoFollow":false, "btnHidden":false, "dist":2760}  // 再暂停
6-click-btn       {"autoFollow":true,  "btnHidden":true,  "dist":0}     // 按钮点击回底
```

真实滚动（原生 scroll 事件路径）结果与合成事件一致：滚到距底 2160px → 暂停+按钮浮现；滚回底部 → 恢复+按钮隐藏。

### 第二轮（移动靶：scrollHeight 持续增长）

- 移动靶确认：1.5s 内 scrollHeight 3724 → 3788（+64px）。
- 暂停：`{"autoFollow":false,"btnHidden":false,"dist":3208}` ✓
- 滑回"差一点"（每次重定位 st=sh-ch-100，dist=100）：5/5 次 `autoFollow=true`（旧逻辑 dist=100≥40 不恢复；RESUME_DIST=150 接住）。✓ 核心修复点
- 按钮：暂停时浮现（实测渲染 rect ~77.3×22，绿底"↓ 回到底部"），点击后 dist=0 贴底并恢复跟随 ✓

### 注意事项

- **程序化设置 scrollTop 也会触发浏览器异步原生 scroll 事件**（CSSOM 规范）。实测中"合成 dispatch + 原生异步事件"对同一次 scrollTop 变更会双触发：合成先置 autoFollow=true，原生随后因 `scrollTop == lastScrollTop` 判为"向上滚"而翻回 false（dist≥40 时）——这是**测试伪影**，真实用户滚轮输入只有原生事件，不受影响。生产代码路径安全：`scrollToBottomIfFollow` 同步 lastScrollTop，异步事件到达时 `scrollTop==lastScrollTop`、dist=0，不触发暂停分支。
- 设计边界（与旧逻辑一致）：跟随态下向上滚 < 40px 仍保持跟随，下一次追加会拉回底部。
- 已知关联问题（本修复未动）：drawTimeline `slice(-20)` 只渲染最近 20 组，运行超 20 轮时旧轮被丢弃、scrollHeight 骤降、scrollTop 被浏览器夹紧（阅读历史时位置会跳动）。
