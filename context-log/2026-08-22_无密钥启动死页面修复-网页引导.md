# 2026-08-22 无密钥启动"浏览器连不上"修复（B2 网页引导 + 自动续跑）

## 现象

`python agent.py --seed 5 --detailed` 在未配置 DEEPSEEK_API_KEY 时：
- 先打印"实时可视化: http://127.0.0.1:8765/"并自动打开浏览器
- 随后才报错"未在 .env 文件中找到 DEEPSEEK_API_KEY"退出
- 进程退出 → HTTP 服务（守护线程）随之消亡 → 浏览器访问 127.0.0.1:8765 显示"连接失败"

## 根因

`main()` 中服务启动 / 浏览器打开先于 API 密钥校验（原 `get_api_key()` 在循环前 `raise SystemExit`）。
密钥缺失时进程直接退出，留下一个"打开了但已死"的浏览器页面。

## 方案比较（用户拍板）

| 方案 | 行为 | 取舍 |
|---|---|---|
| A：无 key 直接报错退出 | 终端报错，不起服务不开浏览器 | 最简；但无 key 时看不到页面，修 UI 必须真跑模型 |
| B1：起服务+网页提示+手动重启 | 页面显示引导，配好 key 后 Ctrl+C 重启 | 中等 |
| B2：起服务+网页提示+自动续跑（**选定**） | 页面显示引导，主线程每 2 秒重读 .env，检测到 key 自动开始 | 体验最好，无需重启 |

- 用户补充约束：运行时省 API 费用本次跳过；**避免截断上下文（会破坏 prompt 缓存），要省优先压缩**；UI 优化单独开对话（缺密钥提示页属 B2 一部分，本次实现）。
- 无 key 时不发任何 API 请求（零消耗）。

## 实现（B2）

- `agent.py`
  - `get_api_key()` → `get_api_key_or_none()`：不再 `raise SystemExit`，未配置返回 None；重复调用重读 .env 支持热加载。
  - `main()`：服务启动 + 浏览器打开 + step0 快照之后检查 key；无 key 时 `state["status"]="no_key"` 并快照 → 打印/记录"等待配置" → `while` 每 2 秒重读 .env → 检测到后 `status` 恢复 `running`、再快照、构造 client 继续。不能在此处 SystemExit（会杀死服务线程）。
- `web/index.html`：新增 `#nokey` 引导块（copy env.example → 填 key → 自动开始），`render()` 按 `s.status==='no_key'` 切换显示。
- `README.md` / `TECH_DESIGN.md`：同步"未配置 key 不退出，网页引导、自动续跑"。

## 验证（--rounds 0，不调 API，实测全过）

用 `python agent.py --no-open --rounds 0 --port 8766`（本机无 .env）：
1. 日志 `21:42:01 未找到 DEEPSEEK_API_KEY：进入等待配置状态`
2. `output/state.json` `status="no_key"`，metric_history 2 次快照（running→no_key）
3. 写入临时 .env（占位假 key）→ 日志 `21:42:35 检测到 DEEPSEEK_API_KEY，自动开始运行`
4. rounds=0 不调 API → "失败：达到循环上限。已点击 0/63" → 正常退出，`status="incomplete"`
5. selftest 全过；临时 .env 已删除（用户原本无 .env）
