# 2026-08-28 去掉 --detailed，默认详细日志

来源：context-log/2026-08-25_待修问题清单.md 第 1 条（--detailed 语义混淆），用户讨论后定案实施。

## 面对的问题

`--detailed` 语义混淆：用户不加 `--detailed` 时，网页「AI 决策过程」卡照样实时显示思考，与直觉不符。

根因（已核实代码）：
- UI 思考显示无条件开启：`agent.chat_stream` 流式 delta 实时 `write_reasoning_live`（SSE reasoning 事件），无开关。
- `--detailed` 只影响日志文件：`logger.log_model_response(detailed=True)` 额外写「模型思考:」（reasoning_content）与「模型调用工具:」（响应侧原始工具调用）。不加时日志也有：每次工具调用+参数+结果（`log_tool_call` 无条件）、最终输出、耗时、轮次。

## 讨论与定案

用户观点：思考过程显示出来比较好（否则等待无反馈，不耐烦），应成为默认用法；不带思考的日志价值低。

讨论确认的事实：
- 「UI 思考显示默认」诉求已天然满足（本就无条件），与 --detailed 无关。
- 不带思考的日志对排查「AI 为什么这么干」无价值（如问题清单第 4 条重复点击，靠 reasoning 才能判断）。
- tests/sim_agent.py 回放靠解析「模型思考:」行（THINK_RE）流式重放思考——不带思考的日志无法驱动思考流 UI 测试。
- 附带收益：--detailed 语义混淆整个消失；DETAILED_LOG=0 环境变量遗留坑（2026-08-06 根因）一并消失。

唯一副作用：--detailed 下思考在控制台打印两遍（流式实时 + write_log 带时间戳整块），过去有「思考刷屏把网址刷出视野」的坑（2026-08-06），默认开启后噪音翻倍。

定案：去掉 --detailed 与 DETAILED_LOG，默认详细日志；思考/工具调用原文块「只写文件、不打屏」，控制台只保留流式实时打印。

## 改动

- agent.py：删 `--detailed` argument、DETAILED_LOG 读取与启动诊断行（保留 main 开头 load_dotenv，密钥加载仍需）；`log_model_response(msg, log_file)` 去掉 detailed 参数；`from dotenv import load_dotenv, dotenv_values` → `load_dotenv`（dotenv_values 仅 DETAILED_LOG 用）；顶部 docstring 更新。
- logger.py：`write_log` 加 `echo=True` 参数（echo=False 只写文件）；`log_model_response` 去 detailed 参数，思考/工具调用原文走 `echo=False`，最终输出照旧打屏。
- 文档：README 快速开始、AGENTS.md「其他」、env.example 的 DETAILED_LOG 说明、agent.py docstring，全部删除 --detailed 相关文案。
- context-log/2026-08-25_待修问题清单.md 第 1 条标记 ✅ 已修复。
- 不动：context-log 历史存档、tests/example_data.txt（历史样例数据，sim_agent 按格式解析，诊断行自然忽略）。

## 测试

- `python tests/selftest.py`：全部自测通过（种子锁定/参数校验/渲染/0 歧义/快照/流式/HTTP 敏感文件拒绝）。
- 探针（probe_logger_echo.py，验证后已删）：控制台只打印「模型输出:」一行；日志文件含「模型思考/模型调用工具/模型输出」三行——「写文件不打屏」生效，且日志格式与之前 --detailed 一致（sim_agent 回放兼容）。
- GetDiagnostics：agent.py、logger.py 无静态错误。

## 决策依据

- 不带思考的日志排查价值低，而详细日志是唯一对排查与回放（sim_agent）都有用的格式 → 默认化。
- UI 思考显示本就无条件 → 无开关可删，语义混淆随 flag 删除消失。
- 控制台重复打印是真实噪音（有 2026-08-06 刷屏前科）→ 用 echo=False 消除，而非接受。
