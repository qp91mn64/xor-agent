# Context Log - HTTP 静态服务泄露敏感文件：SimpleHTTPRequestHandler 不隐藏点文件

创建时间: 2026-08-06
触发场景: 可视化方案 C 实现时审查"服务内容边界"（用户安全顾虑：怕恶意程序/暴露系统目录）

## 现象与风险

- `SimpleHTTPRequestHandler` 服务项目根目录时**不隐藏点文件**：实测 `GET /.gitignore` → 200。
- 若服务根目录含 `.env`，`GET /.env` 可下载密钥（本机 127.0.0.1 范围内，浏览器/本机进程可直接访问）。
- 这不是目录穿越（directory 参数已防止逃逸出根目录），而是"根目录内容无差别可读"。

## 验证（2026-08-06 实测，未触碰真实 .env）

| 路径 | 结果 |
|---|---|
| `/.gitignore` | 200（点文件可下载） |
| `/README.md` | 200（普通文件正常） |
| `/probe_ui_launch.py` | 200（脚本可下载） |

结论：文件只要在服务根目录内、路径写对，即可被下载，**无默认拦截**。

## 修复（agent.py `_is_sensitive_path`）

拒绝（返回 404）：
- 任意路径段以 `.` 开头（`.env`、`.gitignore` 等）；
- 任意路径段以 `.log` 结尾（运行日志含思考/路径信息）；
- 任意路径段以 `probe_` 或 `_` 开头（探针/临时脚本）。

关联约束：服务根目录固定为脚本所在目录 `BASE`（不依赖 cwd），防止从系统盘（如 C:\Users\<用户名>）启动时暴露整个目录。

## 再次收紧（同日）：路径白名单

`_is_sensitive_path` 是黑名单，只挡已知敏感模式，项目根其余文件（agent.py、tools.py、context-log/ 等）仍可经 HTTP 下载。进一步收紧为白名单（agent.py `_Handler.do_GET`）：

- 只放行 `/web/` 与 `/output/` 两个前缀；`/`、`/index.html` 映射到 `/web/index.html`；其余一律 404。
- 目录请求（以 `/` 结尾）一律 404，不再列目录（防枚举 output/ 下文件名）。
- `_is_sensitive_path` 保留作兜底（防未来新增进 web/output 的敏感文件）。
- selftest 断言同步：`/README.md`、`/agent.py`、`/context-log/`、`/output/` 均 404，`/` 与 `/output/state.json` 仍 200。

## 注意

- 该拒绝只覆盖已知敏感模式；新增敏感文件类型（如新密钥文件名）需同步更新 `_is_sensitive_path`。
- 深层约束不变：密钥只在 `.env` 且不入库；HTTP 服务仅绑本机回环 `127.0.0.1`。
