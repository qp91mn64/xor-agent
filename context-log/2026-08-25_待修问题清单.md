# 待修问题清单与后续方向（2026-08-25）

## 一、已知问题

### 1. `--detailed` 语义混淆：没加 `--detailed`，UI 照样显示思考过程

- 现象：测试 SSE 时没加 `--detailed`，网页「AI 决策过程」卡照样实时显示思考。
- 根因分析：`--detailed` 只控制**日志文件**是否记录模型思考与工具调用原文（`logger.py` 的 `log_model_response`/`log_tool_call`），与 UI 显示无关；UI 思考来自 SSE `reasoning` 事件（`write_reasoning_live`），两者是独立链路。用户预期 `--detailed` 是"显示思考"的总开关，实际不是，语义易误导。
- 待修方向：改名/文档澄清（`--detailed` 明确为"详细日志"），或加独立开关控制 UI 思考显示；先定语义再动。

### 2. 最后几个格子显示不出来

- 现象（2026-08-24 真实运行已记录，本次复述）：运行完成时「AI 决策过程」卡最后几个 set_region 未显示，但终端已输出。
- 疑点：最后一轮点击后运行立即结束（coverage==63 判定），UI 最后一次轮询未抓到最终 state.json，或最后几格点击与结束快照时序竞态。SSE 化后是否仍复现待测（理论上 state 事件即时推，可能已修，待验证）。
- 详见 context-log/2026-08-24_实时卡布局方案对比与定稿.md「待修 bug 记录」第 1 条。

### 3. 智能跟随滚动：翻历史后滑回底部很难恢复跟随

- 现象：时间线卡向上翻看历史后，再滑到底部不一定能成功恢复自动跟随。
- 分析：恢复条件是"距底 < 40px"（`scrollHeight - scrollTop - clientHeight < 40`），需真正贴底才恢复；内容持续追加使 scrollHeight 增长，用户滑到底部时若差一点不满足阈值就不恢复，体验上"很难成功"。
- 待修方向：加大恢复阈值 / 增加「回到底部」按钮 / 改为检测 scroll 方向；先定交互再动。

### 4. AI 重复点击已点击过的区域，导致提前终止

- 现象：用户测 `--detailed` 语义的那次运行（日志名 `xor_agent_20260825_215015.log`，**该文件已不在磁盘**：`*.log` 被 .gitignore 忽略且测试后未保留，复现时需重新跑或向用户要日志）AI 重复点击已点击过的区域，消耗点击次数提前触达终止条件。
- 疑点：用户怀疑该轮 AI 改了设计、换了种方案（需看日志确认）；系统提示词已要求"每个非种子区域都要被点击设定过"，但未禁止重复点击；`coverage()` 按去重计数，重复点击不计入覆盖但计入 `click_count`。
- 待修方向：先解析日志确认真实行为，再定是提示词约束还是计数器语义（重复点击是否应计入）。

## 二、后续方向

### 5. 不依赖图片的加载方案

- 用户问题：可视化只需要参数 grid（64 个值）就够了，为何依赖 512×512 PNG 加载？
- 事实：前端已有 heatmap 用 canvas 按 grid 绘制（64 格色块）；主画布 `<img>` 依赖 `/output/step_NNN.png`。`(dx^dy) & a` 渲染逻辑在 numpy 实现，JS 复刻可完全免 PNG。
- 用户约定：**防范，最简方案、跑得快的方案优先，一开始就先摸清楚**（先摸清 JS 复刻渲染的可行性与成本，再定是否实施）。
