# 2026-08-22 HTTP 路径穿越密钥泄露（.env 可被下载）修复

## 现象

HTTP 可视化服务（127.0.0.1:8765）存在 URL 编码路径穿越：访问
`/web/%2e%2e/%2eenv`（= `/web/../.env`）可**下载 `.env` 全文**（含 DEEPSEEK_API_KEY）；
`/output/%2e%2e/agent.py` 可下载源码。实测确认（curl 200 返回文件内容）。

## 根因

`_Handler.do_GET` 的白名单（`startswith("/web/")` / `"/output/"`）与 `_is_sensitive_path`
都用**未解码的原始路径**判断：

- `%2e%2e`（编码的 `..`）不以 `.` 开头 → 敏感检查不拒；白名单 `startswith("/web/")` 仍命中；
- `%2eenv`（编码的 `.env`）不以 `.` 开头 → 敏感检查不拒；
- 随后 `SimpleHTTPRequestHandler` 的 `translate_path` 会 `unquote` + `posixpath.normpath`，
  把路径消解到根目录（BASE）文件 → 下载。

注：原始 `../`（未编码）实测 404，被当前 Python 版本自带防护拦截；但编码形式可绕过，因此必须自己修。

## 修复（agent.py）

`do_GET` 改为**先 `unquote` 再 `normpath` 再做检查**：

1. `raw = urllib.parse.unquote(self.path.split("?")[0])`
2. 目录请求（`raw.endswith("/")` 且非 `/`）一律 404（含 `/web/%2e%2e/` 等编码目录）
3. `path = posixpath.normpath(raw)`，`_is_sensitive_path(path)`（此时 `%2eenv` 已还原为 `.env` 被拒）
4. 白名单改用规范化后的 `path`（`/web/../agent.py` → `/agent.py` → 404）
5. 新增 `import posixpath`、`import urllib.parse`

## 验证

- selftest 新增回归用例（`selftest.py` HTTP 段）：`/web/../agent.py`、`/web/%2e%2e/agent.py`、
  `/web/%2e%2e/%2eenv`、`/output/%2e%2e/%2eenv`、`/output/%2e%2e/agent.py` 均须 404；全部自测通过。
- curl 实测：修复前 `/web/%2e%2e/%2eenv` → 200（.env 全文）；修复后 → 404。
- 正常路径不受影响：`/`、`/output/state.json`、`/web/index.html` 均 200（selftest 覆盖）。
- 测试用占位 .env 与临时文件已全部删除。

## 备注

- 测试时 curl.exe 在 sandbox 下偶发 000（管道/连接怪象，不影响结论；以 selftest 的 urllib 断言为准）。
- 其他 key 泄露面核查结论：key 只经 `get_api_key_or_none()` 读入内存、传给 OpenAI client，
  不进入日志（日志只记录模型文本/工具参数）、不进入 state.json/快照；`.env` 在 .gitignore 中。

## 附：路径穿越是什么（通俗解释，无基础版）

路径穿越 = 用 `..`（"返回上一层文件夹"，和 `cd ..` 一个意思）逃出服务器允许访问的目录，去读别的文件。本项目 `.env`（API 密钥）就在服务根目录，没修之前可被下载。

- 服务器规矩：只放行 `/web/` 和 `/output/` 开头的路径，其他一律 404。所以直接请求 `/agent.py` 会被拒。
- 漏洞路径 `/web/../.env`：安全检查**只看开头**是不是 `/web/` → 放行；但系统真正读文件时按"进 web → `..` 回根目录 → 读 .env"走，最终打开的是根目录的 `.env`。
  - 类比：保安只检查你走进的是不是"房间A"的门，但房间A有后门通走廊，从走廊能进任何房间。
- 编码绕过（本项目实际触发的那种）：URL 里 `.` 可写成 `%2e`，所以 `..`=`%2e%2e`、`.env`=`%2eenv`。安全检查看**原始字符串**：`%2e%2e` 以 `%` 开头而不是 `.`，"以点开头=敏感文件"的规则被绕过；服务器真正处理时把编码还原成 `..` 和 `.env`，照样读到文件。
- 危害：能访问本机 8765 端口的人即可下载 `.env` 拿到 DeepSeek API 密钥，用来刷你的额度（花你的钱）。
- 修法：检查前先把路径"翻译"成真面目——`unquote`（还原 % 编码）+ `normpath`（折叠 `..`）。折叠后 `/web/../.env` → `/.env`，明显在白名单外 → 404。
- 一句话：**进门检查只看表面开头，真开门时系统会走 `..` 绕路，两套逻辑不一致就被钻了空子；把路径先归一化成真面目再检查即可堵住。**

## 附 2：嵌套编码（%252e）防得住吗——解码深度一致性

结论：**防得住**（实测 `%252e`（= 双重编码的 `..`）等全部 404；已加入 selftest 回归）。

关键原理：**检查和解码共用同一条输入（原始 self.path），各自恰好解码一层**，所以"检查看到的路径"就是"实际拼文件用的路径"，不存在两套不一致的逻辑：

- 检查流：`unquote(self.path)` 解 1 层 → `normpath` → 白名单/敏感检查
- 解析流：`translate_path(self.path)` 也解 1 层 → normpath → 拼 BASE 下的文件

设请求是 k 层编码的恶意字符（k=1 是 `%2e`，k=2 是 `%252e`，…）：

- **k=1**：检查流解出真面 `..`/`.env` → normpath 折叠或敏感检查拒绝 ✓
- **k≥2**：检查流解 1 层后仍是**字面** `%2e%2e`（不是 `..`），normpath 不折叠、敏感检查不拒；但解析流同样只解 1 层，拼出的磁盘文件名是字面 `%2e%2e%5c...` 之类——**磁盘上不存在这样的文件** → 404 ✓

也就是说：穿透要成立，必须"检查漏过、解析命中真实文件"。解析流解 1 层后只有两类结果：真面 `..`/点文件（检查流同时看到的也是这个，被拒），或字面 `%XX`（磁盘无此文件）。中间没有第三种可能。

"编码是数学运算得到"（XOR、base64、进制变换等）：URL 路径只有**一种**转义机制（百分号编码 `%XX`），任何运算的产物最终都以 `%XX` 或字面字符落入 URL；所以防御不看"编码有多花哨"，只看**解码深度是否与解析一致**。本项目检查流与解析流同源同深度，任意层数都安全。

补充边界（同样实测/推理覆盖）：
- 反斜杠变体 `%5c`（Windows 分隔符）：单层编码 `..\` 以 `.` 开头被敏感检查拒；双重编码解 1 层后 `%5c` 仍是字面字符，拼出的文件名不存在 → 404。
- `..` 折叠后仍落在白名单内（如 `/web/x/../index.html` → `/web/index.html`）：无害，不泄露。
- 若某天重构让检查流的解码深度 ≠ 解析流（例如只检查不解码，或检查用另一份输入），漏洞会重新出现——selftest 的嵌套编码用例就是防这个的回归网。

## 附 3：隐藏字符与"数学运算拆解"防得住吗（实测）

结论：**都防得住**；唯一加固点是控制字符（现已在 do_GET 拒绝，返回干净 404）。

**数学运算拆解**（如把 `n` 拆成 `0x6d+0x01`）：http.server 对 URL 路径只做两件事——百分号解码（`%XX`→字节）和 normpath（折叠 `..`），**不做任何算术求值**。`0x2e+0x2e` 写进 URL 就是 9 个字面字符，拼出的磁盘文件名不存在 → 404。实测 `/web/0x2e+0x2e/0x2eenv`、`/web/0x6d+0x01/0x2eenv` 均 404。
- 本质：URL 路径的解码是**确定性的字符替换**，不是运算；只要解析器不"计算"，数学公式就不会生效。

**隐藏字符**（全角句点 `．` U+FF0E、零宽空格 U+200B、过时超长编码 `%c0%ae`）：文件系统只把 ASCII `.` `/` `\` 当特殊符号，这些 Unicode/变体字符都是普通字符，构造不出 `..` 或点文件；即使夹进路径，拼出的文件名在磁盘上不存在 → 404。实测全 404。

**变体选择符等同类 Unicode 字符（实测 404）**：Variation Selectors（U+FE0E/FE0F，`%EF%B8%8E`/`%EF%B8%8F`）、零宽连接符 ZWJ（U+200D）、右向左覆盖 RLO（U+202E）——夹在 `..` 中间、缀在前后、单独成段，全部 404。原理同上：文件系统按码点看待，不做"前导字符+修饰符=特殊字符"的组合语义；`..`+VS 不是 `..`，normpath 不折叠，拼出的文件名不存在。
- 唯一真正的风险面不是绕过，而是**视觉欺骗**：RLO 可让回显顺序反转（`.env` 显示成 `vne.`）。本项目请求路径从不回显到页面/日志（页面只渲染 state.json 的模型数据），且 HTML 有 `esc()` 转义，故无实际影响。

**控制字符（唯一发现问题，已修）**：空字节 `%00` 实测会让服务器**异常断连**（RemoteDisconnected，open 含 `\x00` 的路径抛 ValueError 而非 OSError，绕过了 send_head 的 404 捕获）。不构成泄露，但行为不当。修复：do_GET 在 normpath 后拒绝任何含 ASCII 控制字符（0x00-0x1F、0x7F）的路径，返回干净 404；换行 `%0a`、`%2f` 变体实测本就 404。selftest 已加 `/web/%00`、`/web/%0a` 回归用例。
