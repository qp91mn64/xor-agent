# 每轮思考与最终总结在可视化里静默消失（2026-10-17 修复）

一句话：**"每轮的思考/正文/工具调用"原来没有按轮落盘的通道**——思考只挂在点击条目上、实时思考文件被下一轮覆盖、模型正文压根没有通往网页的路。结果是没有 set_region 点击的轮次（只查看/只评估/只输出总结）思考静默消失，最终总结从不显示。修复后 `state.rounds` 是每轮决策的唯一权威来源。

## 一、现象（用户报告）

1. **第 1 轮的思考后面就被吞了、找不到**：运行中先在时间线上看到第 1 轮大段思考，进入第 2 轮后它凭空消失。
2. **最后输出总结那一轮，思考突然消失，总结也没出现**（终端照常打印思考与总结）。

设计原则（用户明确）：**确保有关信息可见，而不是不提醒就突然消失**。

## 二、根本原因（实测证据）

同一份"轮次思考"有 3 条互不相通的通道，职责错配：

| 通道 | 内容 | 生命周期 | 缺口 |
|---|---|---|---|
| `reasoning_live.json`（+ SSE `reasoning` 事件） | 仅**当前轮**思考全文 | 下一轮第一个 delta 到达即整文件覆盖；运行结束删除 | 上一轮思考被覆盖后，界面上再无来源 |
| `state.clicks[].reasoning` | 思考**挂在点击条目上**（`set_region` 入参） | 随 state 落盘 | **没有 set_region 的轮次完全没有落盘**：只查看（`view_region`）、只评估（`evaluate`）、只输出总结的轮次全部中招 |
| 日志文件 | 全部思考 + 正文 | 永久 | 网页不读它 |

- 第 1 轮现象 = 通道 1 被第 2 轮 delta 覆盖，且该轮只查看种子（无点击）→ 通道 2 也没有记录。
- 末轮现象 = 该轮只评估 + 输出总结（无点击）→ 通道 2 无记录；随后 `clear_reasoning_live()` 删除通道 1 → 思考消失。
- **模型正文 `msg.content`（末轮的最终总结）没有任何通往网页的通路**：`chat_stream` 只把 `reasoning_content` 经 `write_reasoning_live` 推给 web，`msg.content` 只进日志文件与控制台（与 context-log/2026-09-07 记录的"最终总结不显示"同一根因）。
- **工具结果也从来没进过 state**：`result` 只经 `log_tool_call` 进日志；`set_region` 的结果顺带以"点击"形式进了 `clicks`，`view_region` / `evaluate` 的结果在 state 里完全不存在。可视化拿不到结果，因果链是断的（表现为"顺序不对、被割裂"）。

**探针实测（一次性脚本 `_probe_reasoning_rounds.py`，验证后已删）**：对 3 份真实运行日志按轮统计思考长度与 `set_region` 次数——

| 日志 | 有点击的轮次 | 思考被静默丢弃的轮次 |
|---|---|---|
| `tests/example_data.txt`（8 轮） | 2–5 | 第 1 轮 59325 字符 + 6/7/8 轮 |
| `tests/example_data_2.txt`（7 轮） | 3–5 | 第 1 轮 82299、第 2 轮 2940、第 6、7 轮 15689 |
| `xor_agent_20261017_010113.log`（7 轮，用户本次真实运行） | 2–5 | 第 1 轮 56102 字符 + 6、7 轮 |

即：**每份真实日志都有 3–4 轮思考在任何地方都没落盘**，第 1 轮就丢 5–8 万字符。

## 三、最终技术方案（当前代码）

**后端：`state.rounds` 是每轮决策的唯一权威来源**

- `xor_world.record_round(round_id, reasoning, content, calls)`：一轮（= 一次 API 请求）的全部工具执行完后落一条 `{round, reasoning, content, calls, tools, clicks}` 并快照；`calls = [{name, args, result}]` **按实际调用顺序**记录，`tools` 是由 `calls` 派生的计数（只用于组头概览）。
- `agent.py`：主循环 `try/finally`，一轮一条（API 失败上抛时不落空记录）；`clicks` 去掉 `reasoning` 字段（原来同一思考在 63 个格子上各抄一份），`set_region(index, value, round_id)`；`tools.execute_tool` 删掉已无意义的 `reasoning` 形参。
- **每轮正常结束不再 `clear_reasoning_live()`**：实时文件只承载"当前轮流出的思考"，由下一轮 delta 覆盖；提前清文件会把进行中那轮的流式思考从界面上抹掉。只在运行结束与 API 失败时清理。
- `sim_agent.py` 同构：`output` 事件（= 该轮模型正文）到达时 `record_round`，回放链路与真实链路一致。

**前端：时间线 = 按真实发生顺序的一条流**

每轮依次是「轮次标题 `第 N 轮 · 格数 · 工具统计` → 该轮思考（流式，绿）→ 点击轨迹紧凑一行 `#49→43(原0) …` → 该轮模型正文（末轮的正文即最终总结，蓝左线）」，**全部轮次都渲染、不截断**（卡内滚动；曾硬编码只渲染最新 20 组，`--rounds 30` 时前 10 轮会静默消失）。

- **进行中轮次只有一条**：流式思考与"该轮工具已开始执行"的点击是同一轮的两种到达，前端把实时全文并进**同一分组**（`liveGroup.reasoning = liveText`），仅在"该轮还没有任何痕迹"时才新开组，末尾按 round 重排。
- **不展开工具调用与结果**：完整参数与结果只留在 `state.rounds[].calls`（state.json）里按需查看。
- 流式期间只更新进行中那组的 `#live-why` 文本节点，不重建整棵时间线（结构签名 `lastSig` 刻意不含进行中轮的思考长度）。
- 旧格式 `state.json`（只有 clicks、无 rounds/calls）自动回退：思考从 clicks 取、不画调用行，历史运行目录仍可查看。

## 四、三次修改（做错与纠正，供复盘）

1. **第一次：分层显示**。把「思考 / 点击 / 正文」按信息类型拆成三段并列。用户实测直接反馈"为什么割裂思考与结果""工具结果夹在中间、不按时间顺序""界面把人绕晕"。→ 改为按时间顺序一条流。
2. **第二次：结果展开**。为补上"工具结果不在 state"的缺失，我把 72 条工具返回逐行展开成 `[1] 评估进度 → 已设定 0/63 …`。用户否决："无需展开""看着就头大""你有 1M 上下文，用户是人类"。→ 数据进 `calls` 存档，界面只留组头概括（`设定×15` / `评估×1`）+ 点击轨迹。
3. **第三次：进行中轮次画了两遍**。静态排版已对，但流式过程中出现两个「第 N 轮」小标题、点击行夹在中间。根因是实时思考组与该轮点击组各自建组未合并。→ 改为每轮唯一一条。**上一版校验脚本只喂静态最终 state，完全没覆盖"过程态"，所以没拦住。**

## 五、测试方式与结果

1. `python tests/selftest.py` —— 全过。`test_record_round()` 断言：无点击轮次的思考/正文照样落盘、**工具调用与结果按调用顺序保存**、`tools` 计数由 calls 派生、`clicks` 不再重复存思考；`test_sample_data()` 增加"每轮都必须有 think 事件"断言。
2. `python tests/sim_agent.py --speed 100 --no-open --exit`（回放 `example_data.txt`，63/63 完整）→ 运行文件夹 `output/<运行ID>/`。
3. `python tests/check_timeline.py [state.json]` —— **全部通过**：
   - index.html 结构检查（时间线函数齐全、无 `slice(-20)` 式截断）；
   - **流式进行中状态**（`check_live_merge`）：第 5 轮思考 + 点击陆续到达 1/2/3 个、随后第 6 轮开始流式 → 每轮标题仅 1 次、顺序「标题 < 思考 < 点击」成立、第 5 轮落盘后不被第 6 轮实时文本覆盖；
   - 8 轮思考与 8 轮模型正文（含 892 字符最终总结）全部可见；
   - 63 次点击轨迹全部可见且跨轮顺序正确；
   - **反向断言：工具结果文本不得出现在页面上**（只在 state.json 里）；
   - 旧格式目录走回退、不误报。
4. **真实主循环链路**（不是回放器）：用假流式 client 替换 `agent.OpenAI` 跑 `agent.main()`（一次性探针，验证后已删）——第 1 轮只 `view_region`、第 2 轮只输出总结，两轮思考与总结都落进 `state.json`，`clicks` 无 `reasoning` 字段，运行结束 `reasoning_live.json` 已删除。**该验证已完成、不常驻**；只有再改动主循环的每轮落盘接法时才需重做一次。
5. 体积：`state.json` 17.2 KB（旧格式，无 rounds）→ 73.1 KB（含第 1 轮 5.9 万字符思考）+ 约 7KB（72 次工具结果）。增长全部来自"原本根本没存的信息"。

## 六、经验

- **"信息挂错了对象"比"没保存"更隐蔽**：思考挂在点击上，看着有落盘、有渲染，但只在有点击的轮次成立；缺的轮次不留任何痕迹（无报错、无空组），所以用户只看到"突然消失"。排查时必须按"每个轮次是否都有来源"逐轮核对，而不是看代码里有没有 `reasoning` 字段。
- **工具结果不是附属品，是决策链的一环**：模型的下一步动作由工具返回内容直接决定（终端也同步打印）。只把"点击"搬进可视化、把 view/evaluate 的结果留在日志里，等于剪断因果链。
- **临时文件不能当唯一存档**：`reasoning_live.json` 是"当前轮中间态"，被覆盖是它的设计行为；错在正式记录只有它一条路。分清"中间态"与"权威存档"。
- **界面别自己发明分层**：时间线上本来就线性发生的事，就线性排；分类是额外概念负担。
- **数据要全，界面要省**：这是两件独立的事——存档完整性按"以后能不能复原现场"定，显示密度按"人类一眼能看多少"定。同一个改动里我两次走偏（先是不进 state，后是全展开），就是把两者混为一谈。
- **只测最终态会漏掉过程态**：流式 UI 的状态空间是"数据累积的中间态"（思考在长、点击在追加、该轮还没落盘）。回归必须显式喂中间态——第三次 bug 正是只喂了静态 state 才漏掉。
- **证据链两件套**（可复用）：数据层按轮统计脚本 + 渲染层用真实 `state.json` 驱动一份"渲染口径镜像实现"。不开浏览器就能断言"每轮思考/正文/轨迹都可见、顺序对、该收起的没展开"，`tests/check_timeline.py` 已常驻。
- **别拿 Node 当测试运行时**：第一版检查写成 `tests/webcheck_timeline.js`（用 node 跑前端真实函数，最忠实），用户当即指出这是"引入新依赖、假定用户装了 node"——项目依赖只有 requirements.txt / DEPENDENCIES.md 里的 Python 包。已改为纯标准库的 `check_timeline.py`（手工复刻前端规则，文件头写明"改前端须同步改本文件"，并加结构前置检查兜漂移）。随后用户又指出"装了 Node 才做的可选校验"这层概念也多余，遂彻底删除，脚本内不再出现第三种运行时。

## 七、环境限制（本次遇到）

DSH 沙箱（workspace-write）下 **pwsh 的写/删/复制文件一律被拒**（`PermissionError` / `UnauthorizedAccess`，含 `Copy-Item`、`Remove-Item`、python `write_text`），只有 write 工具能改工作区文件。因此本次**无法把 `xor_agent_20261017_010113.log` 复制成第 3 份样例**（该文件被 `.gitignore` 的 `*.log` 忽略，暂不纳入版本控制）；两个一次性探针也只能由用户在沙箱外删除（已删）。

## 八、后续

- 常驻测试三样：`selftest.py`（含 `test_record_round`，锁死"无点击轮次也要落盘"的口径）、`sim_agent.py`（真实日志回放，浏览器实测）、`check_timeline.py`（渲染层可见性与顺序断言，纯标准库）。
- `check_timeline.py` 出场时机已写进文件头与 README「测试」节：**改动 `web/index.html` 时间线渲染、或改动 `state.rounds`/`clicks` 数据口径后必跑**；也可在任意一次回放/真实运行后抽查。
- 负例自测过两种：把某轮思考与正文都抹掉（模拟旧 bug 的"有记录无内容"）→ 报"空白组"；把实时合并逻辑换回旧写法 → 报"「第 5 轮」标题出现 2 次 + 顺序不对"。

## 徒手补充

DeepSeek-V4.1-Flash改了好几遍，除了测试脚本用node，后来发现用户可能根本没node就换Python以外，还出现过让人始料未及的设计问题：两个类似"第5轮"的小标题，同时新增信息也出现在中间，就像工具结果夹在中间一样，然后又只剩一个小标题，影响阅读。指出问题之后，模型又自作主张地展开工具调用结果，接着指出太复杂，还从原来简洁的呈现里面截取中间带`#49→43(原0)`这种结果的一轮当作示例，模型是把呈现的信息改回去了，但是老毛病仍在，只好展开预期结果，这次的提示词就像这样：

```
显示是一个过程（毕竟是流式输出。）——最终结果排版对了，中间模型操作工具的时候，`#49→43(原0) #50→27(原0)`夹在中间的老问题**又出现了**（而且我不会把这个叫“工具调用结果”了，以免你重走展开结果的老路），同时伴随两个“第5轮”信息。我的语气就是按照时间顺序显示：思考->模型调工具(结果呈现方式还是简洁风格)->最终输出，不出现两个“第5轮”小标题。（:(）
```

然后模型终于不重走老路了。看来DeepSeek-V4.1-Flash或者在设计心理学上相对欠缺（没考虑用户），或者会自作主张地修改导致偏离预期，非要把问题和预期展开才能避免模型乱改。或者模型眼里“工具结果”就是复杂的一长串信息，我的预期是像`#49→43(原0)`这样简洁的。
